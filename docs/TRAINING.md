## 四、阶段详解

### 阶段 1：需求讨论与技术选型

**对话模式**：多轮对话，逐步明确需求

**关键决策过程**：

```
用户：我要做一个 AI 文音画创作项目，后端用 Java 还是 Python？
AI：Python，因为 AI 生态（TTS/图像/视频）几乎都在 Python。

用户：需要数据库吗？
AI：需要 PostgreSQL/MySQL + Redis

用户：需要 Dify/智能体吗？
AI：不需要。你的需求是「创作工具」不是「聊天机器人」。
    格式控制用 Prompt 模板 + Schema 校验 + 重试更可靠。
```

**学到的**：
- 给 AI 充分的上下文（API 文档、具体需求）
- AI 能快速给出技术选型对比表
- 不要跳过讨论阶段，直接写代码会返工

---

### 阶段 2：输出设计文档

**做法**：让 AI 生成完整的 `DESIGN.md`，包含：
- 项目结构
- 页面设计（带 ASCII 布局图）
- 核心功能详细设计（Prompt 模板、Schema 定义）
- 数据模型（6 张表）
- API 接口设计
- 实施步骤（Phase 1-5）

**Prompt 示例**：
```
请先出一个完整详细，按步骤的功能设计文档，
后续让 AI 读取这个文档来实施。
```

**学到的**：
- 设计文档是后续所有开发的「合同」
- 文档越详细，后续代码生成越准确
- 文档可以反复迭代，比改代码成本低

### 阶段 3：生成项目骨架

**做法**：AI 读取设计文档，一次性生成 65+ 个文件

**生成顺序**：
```
后端核心 → 数据模型 → Schema → 服务层 → Prompt 模板
→ API 路由 → Celery 任务 → FastAPI 入口 →
前端脚手架 → 路由 → API 封装 → 页面组件 →
Docker 配置 → README
```

**关键 Prompt**：
```

新建个目录，区分前后端
```

**学到的**：
- 一次性生成完整骨架比逐文件创建效率高 10 倍
- 生成后需要检查目录结构是否合理
- `.env` 这种配置文件需要单独处理（不能含真实密钥）

### 阶段 4：启动调试

**遇到的问题与解决**：

| 问题 | 原因 | 解决方式 |
|------|------|---------|
| `Directory './storage' does not exist` | 相对路径 + 目录不存在 | 改用绝对路径，启动时自动创建 |
| `ModuleNotFoundError` | Celery 没自动发现任务 | 改用显式 import |
| `Illegal header value b'Bearer '` | .env 文件路径错误 | 改 env_file 为绝对路径 |
| `Invalid API Key` | .env 中 API Key 未填 | 填入真实 Key |
| 401 Unauthorized | API Base URL 错误 | 改为套餐对应的 URL |

**学到的**：
- 启动报错是正常的，AI 能根据错误日志快速定位
- `.env` 的路径问题在 Celery Worker 和 uvicorn 中表现不同
- `@lru_cache` 会导致配置缓存，改 .env 后需要重启进程

### 阶段 5：核心功能实现

**播客生成流程**：
```
用户输入 → LLM 生成脚本（JSON）→ Pydantic 校验
→ 并发 TTS 合成 → pydub 拼接 → 保存文件 + 数据库
```

**关键代码模式 — 格式控制三板斧**：

```python
# 1. Prompt 模板（包含完整 JSON 示例）
prompt = PODCAST_SCRIPT_PROMPT.format(...)

# 2. API 层强制 JSON
response_format={"type": "json_object"}

# 3. Pydantic 校验 + 重试
script = llm_service.generate_structured(prompt, PodcastScript)
```

**学到的**：
- AI 生成的 JSON 格式不稳定，必须有校验 + 重试
- Prompt 里给完整示例比描述格式更有效
- 情绪枚举要多留余量，LLM 会生成意料之外的值

### 阶段 6：联调修复

**典型问题链**：

```
问题：生成的文件无法播放
  ↓
排查：curl 测试 API → 500 错误
  ↓
定位：数据库存的是相对路径 ./storage/audio/...
  ↓
根因：.env 中 STORAGE_PATH=./storage 覆盖了代码默认值
  ↓
修复：注释掉 .env 中的 STORAGE_PATH，改用代码计算绝对路径
  ↓
清理：批量更新数据库中的旧路径
```

**学到的**：
- 让 AI 先看日志再修，不要猜
- `curl -s -o /dev/null -w "HTTP %{http_code}"` 快速测试 API
- 路径问题是最常见的坑，一律用绝对路径

## 八、常见问题 FAQ

### Q1：Worker 挂了怎么办？
```bash
ps aux | grep celery          # 检查是否活着
pkill -f "celery.*worker"     # 杀掉旧进程
celery -A app.tasks.celery_app worker --loglevel=info &  # 重启
```

### Q2：生成的任务卡在"排队中"？
- 检查 Celery Worker 是否启动
- 检查 Redis 是否运行：`redis-cli ping`
- 超过 10 分钟的任务会自动清理

### Q3：文件生成了但无法播放？
- 检查数据库中的 `audio_file_path` 是否为绝对路径
- 检查文件是否存在于该路径
- 检查 `.env` 中的 `STORAGE_PATH` 是否被覆盖

### Q4：AI 生成的 JSON 格式不对？
- 已有自动重试机制（最多 3 情绪枚举值不够用？）
- 在 Schema 的 Enum 中添加新值
- 在 TTS 服务的 `EMOTION_TO_STYLE` 中添加对应映射
- 在 Prompt 模板中告知 LLM 可用的完整情绪列表

### Q5：情绪枚举值不够用？
- 在 Schema 的 Enum 中添加新值
- 在 TTS 服务的 `EMOTION_TO_STYLE` 中添加对应映射
- 在 Prompt 模板中告知 LLM 可用的完整情绪列表
